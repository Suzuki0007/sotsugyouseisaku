# CT 指示書を書くときの決まり（MUSE.AI 向け）

作成：2026-11-20（実装担当：Claude Code）
目的：指示書・会話 CSV・仮素材を、このプロジェクトの作りにそのまま合う形で書いてもらうため。
ここに合っていない所は実装側で読み替えるが、読み替えるたびに確認と手戻りが増えるので、最初から合わせてもらえると速い。

---

## 1. 名前の付け方

| もの | 決まり | 例 | 今までの指示書との違い |
|---|---|---|---|
| シーン | `Stage<層>_<番号>`。ボスは `Stage_<層>_Boss` | `Stage1_4`（T字通路）、`Stage_1_Boss` | 指示書の `Stage1_TCorridor` → `Stage1_4` にした |
| フラグ | `Flag_<場所の略>_<名前>`（英語の単語をつなげる。大文字の区切り） | `Flag_TC_DoorEventDone`、`Flag_Shosai_Q1Clear` | 指示書の `FLAG_TC_DOOR_EVENT_DONE` → 左の形にした |
| 会話 ID | `F<層>_<番号か場所の略>_<場面>` | `F1_TC_DoorFirst`、`F1_TP_Intro` | 仮の ID のままでよい（番号が決まったら差し替える） |
| 出現位置 ID | `From<来たシーン>`（どこから来たか） | `FromStage1_3`、`FromWestRoom` | |
| 場所の略 | 書斎＝`Shosai`、T字通路＝`TC`、上陸＝`Land`、ティンパニ部屋＝`Timpani` | | 新しい場所は指示書で略を決めてよい |

- 同じ名前がすでにあれば、今あるものを優先する（新しい方の名前を変える）。
- フラグは基本「セーブする」。戦闘中だけ・その場だけの物は「セーブしない」と書く。

## 2. 座標とマップ

- **1 マス＝100px**。マップの絵の大きさがそのままマップの大きさ（2160×1440 なら 21.6×14.4 マス）。
- **座標の基準を必ず書く**：「中心」か「左上」か（書斎の指示書は中心、T字通路は左上で、混ざっていた）。**おすすめは「中心」**（Unity の絵の置き方と同じ）。
- 画面：ウィンドウは 16:9 だが、**マップが映るのは中央の 4:3**。カメラが映すのは **1440×1080px**（14.4×10.8 マス）。それより大きいマップは、カメラがノアを追い、絵の端で止まる。
- 歩ける範囲は「四角・円・多角形の組み合わせ」か「白黒のマスク画像」で書く（例：横の通路 x180〜1980・y180〜540）。
- **ノアの当たり判定は足元**：キャラの位置から下へ約 1 マス（中心が 0.61 下、半径 0.40）。
  - **出現位置と、入ると動く範囲（出口・イベントの開始ライン）は 1.2 マス（120px）以上離す**（重なると着いた瞬間に動く。T字通路で起きた）。
  - 調べる範囲は、物の手前（南側）に置く。隣どうしの調べる範囲（扉とシグルなど）が重ならないようにする（重なると近い方が選ばれ、意図しない方になる）。
- 置く物どうしの間隔：歩いて回り込めるように、物と物の間は 1 マス以上あける（書斎の本棚がティンパニに寄りすぎていた）。

## 3. 会話 CSV

- 列は **5 列**：`会話ID, キャラ, 表情, 名前, 本文`（1 行目は見出し。列が足りない行は取り込めない）。
- **ID を書いた行から、次の ID までが 1 つの会話**。ID が空の行は前の会話の続き。`#` で始まる行は演出のメモ（取り込まれない）。
- キャラ：`Noah`・`Sigle`（立ち絵あり）。それ以外の人物（ティンパニ・手紙・？？？ など）は **キャラを空にして「名前」の列だけ**。
  - シグルが名乗る前は キャラ=`Sigle`・名前=`？？？`。名乗ったあと（書斎の紹介から）は名前の列を空にする（「シグル」と出る）。
- **地の文（話し手のない文）は使えない**。説明はノアの心の声 `(…)` にする。操作の説明だけは、キャラを空・名前を「操作」にした行で出せる（書斎の調律の説明）。
- 表情：`通常`・`笑顔`・`怒り`・`悲しみ`・`驚き`・`困り` の 6 つ（今の立ち絵は「通常」だけなので、ほかも通常の絵になる）。
- 長さ：**1 文 40 字まで、1 回の会話 10 文まで**。長い場合は会話を 2 つに分ける。
- 書き方：`、、`（読点 2 つ）で間を表す。心の声は `(…)`。ノアの一人称は「ボク」。
- **会話の途中に演出を挟む場合は、会話 ID を分ける**（例：触れる前 `F1_TC_DoorFirst`／触れたあと `F1_TC_DoorFirst2`）。1 つの会話の途中で演出は止められないため。

## 4. 指示書に毎回書いてほしいこと

1. **どこまで変えてよいか**（1 行でよい）：
   - 会話：「案（口調・内容を調整してよい）」か「確定（変えない）」か
   - 配置・数値：「目安（実装側で調整してよい）」か「厳守」か
2. **座標の基準**（中心か左上か）と、マップの大きさ。
3. **前のシーンとのつながり**：どの出口から来て、どこへ行くか、出現位置。
4. **範囲外**（今回作らない物）と、そのための受け口（出口だけ・フラグだけ など）。
5. **受け入れ条件**（チェックリスト）。今回のような形でよい。
6. 未定の所は「未定」と書く（実装側で勝手に決めない。決めたら報告する）。

## 5. 実装側から返すもの

実装のあと、実装側は **「指示書との違いの報告」** を返す（変えた名前の対応表・変えた座標と理由・足した物・未定のまま残した所・確かめられなかった所）。次の指示書は、その報告と **2_今のゲームの状態.md** を前提に書いてほしい。

## 6. 仮素材

- 仮素材は大きさと位置の確認用。**本番の絵は同じファイル名で上書き**すれば差し替わる（大きさが変わるなら座標の表も更新）。
- 各フォルダに README（ファイル名・大きさ・置く位置・何に使うか）を付ける（今の形でよい）。
- キャラ（ノア・シグル）の絵は、今あるプレイヤーの絵を使うので仮素材は要らない。**シグルの後ろ向きの絵はまだない**（必要な場面では「後ろ向きが要る」と書く）。
