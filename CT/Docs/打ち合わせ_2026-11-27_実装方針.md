# 11/27 打ち合わせのまとめと実装方針

打ち合わせの議事録をもとに、**今あるもので作れること**・**新しく作るとよい機能**・**開発の進め方**をまとめた文書です（2026-11-27）。
決まっていないことは最後の「決めてほしいこと」にまとめました。

---

## 1. 打ち合わせで決まった方向（要点）

| 項目 | 方向 |
|---|---|
| ゲームの形 | 絵になるイベントシーン（30〜40）をつないで作る。1シーンを短編のつもりで作る |
| 遊び | 敵・HP・攻撃は**なし**。追いかけてくる黒い目のような「演出としての怖さ」はある |
| 文章 | 必要最低限。**ノアに感想を言わせない**。語り（モノローグ）だけで進める案もある |
| 話 | 表面はシンプル。父親・フレネミーの裏の事情は、探すとわかる程度に匂わせる |
| 並べ方 | シーンを切り分けて作り、並べ方で見え方を変える。ランダムな順番の案もある |
| 分担 | チャプターごとに担当を分ける。チャプターの間は鍵のかかったドアでつなぐ |
| 見た目 | 白を基本にして雪を降らせる。ビネット・光漏れ・レンズフレア。塔の外は黒か青空 |
| 字幕 | 飾らない太い字を、画面の中央より少し下に大きく出す（映画の字幕のように） |
| 音 | ピアノのソロが合う。儚くない場面の曲を変える |
| 終わり | エンディングは複数。最後は塔が止まって終わり、塔がどうなったかは見せない |

## 2. 今あるもので、すぐ使えること

すでにある仕組みで、打ち合わせの案の多くが作れます。

| 打ち合わせの案 | 使える仕組み | 場所 |
|---|---|---|
| 雪を降らせる・塔の中でも雪 | 天候「雪」（範囲・イベントで切り替え） | `Resources/Presentation/Weather_雪` |
| 白ベースの色・儚い色調 | 色調のプリセット（彩度・暖色寒色・暗い所の色） | `Mood_*`・`Docs/演出の作り方.md` |
| 画面の外側を暗くする（ビネット） | 色調のプリセットの「周辺の暗さ」（強さ・ぼかし・色） | `MoodPreset` |
| 粒子・にじみ（古い写真っぽさ） | 色調の「粒子（Film Grain）」「にじみ（Bloom）」 | `MoodPreset` |
| 長押しで直す・押すと増える（墓を掘る） | 手の動作（長押し・繰り返し・回す。終わり近くで重くなる） | `Gesture_墓を掘る` など 6 種 |
| 直したら光る | 波紋「光が灯る」・色の戻り具合 | `Ripple_*`・`ColorRestoreEventAction` |
| 急に過去が始まる | 回想（色が抜けてから入る） | `Flashback_回想`・`Flashback_埋葬` |
| 絵になる1枚 | 1枚絵を出す・閉じる | `StillShowEventAction` |
| 字幕だけで見せる | シネマの帯＋字幕 | `CinemaEventAction`・`SubtitleEventAction` |
| 鍵のドアで次のチャプターへ | アイテム（鍵）で開く扉・フラグ・オートセーブ | `Docs/アイテム連動イベントの作り方.md` |
| 黒い目が追いかけてくる | 上陸の後の「怪物から逃げる」（Stage1_1） | `rules/scenes.md` の Stage1_1 |
| マップの見た目（色むら・霧・光） | 今日作ったマップの見た目の部品 | `Docs/マップチップの置き方.md` |

## 3. 新しく作るとよい機能

打ち合わせの案のうち、今の仕組みにないものです。**重さ**は作る手間の目安です（小＝半日・中＝1〜2日・大＝3日以上）。

### A. 見た目（次回の発表に効く物）

| 機能 | 中身 | 重さ |
|---|---|---|
| **光漏れ** | 画面の左右にオレンジの光を常に重ねる（カメラのフィルター越しのような見え方）。強さ・色・ゆらぎを色調のプリセットと同じように切り替える | 小 |
| **レンズフレア・太陽のギラつき** | 光の点から画面に向けて輪を並べる。URP の Lens Flare が 2D で使えるかを先に試す。使えなければ絵を重ねる形で作る | 中 |
| **画面の縁を決める** | 画面が真四角に見える問題への対策。ビネット・縁のフェード・枠の決まりを、色調のプリセットの1項目にする | 小 |
| **字幕の大きな太字** | 字幕の字の大きさ・太さ・位置（中央より少し下）を設定できるようにし、既定を映画の字幕の形にする | 小 |
| **塔の外を黒か青空に** | 部屋の外側の色（黒・空の絵）をシーンごとに選べるようにする | 小 |
| **床の色を寒色に寄せて試す** | 床の絵を描き直す前に、場所の色味（AreaTone）・地面の色むらで寒色寄りを試し、北川さんと比べる | 小 |

### B. 語り方

| 機能 | 中身 | 重さ |
|---|---|---|
| **語りの会話（モノローグ）** | 立ち絵も名前もなしで、「彼女は」「男は」の文だけを字幕の形で出す。話し手に「語り」を足し、会話の CSV からそのまま使う | 小〜中 |
| **間（ま）の部品** | 「…」や何も起きない間を置く部品（字幕なしで待つ・キャラが向きだけ変える）。今の「待つ」でも作れるが、名前のついた部品にしてプランナーが探しやすくする | 小 |
| **調べると分かる裏話** | 調べる物に「見つけた記録」のフラグを立て、集めた数でエンディングや語りを変える（裏の事情を探した人だけが気づく） | 中 |

### C. ゲームの組み立て

| 機能 | 中身 | 重さ |
|---|---|---|
| **チャプターの型** | 1チャプター＝1シーン。入口・出口（鍵のドア）・オートセーブ・最初の一枚絵がそろった空のシーンを、メニュー1つで作る | 中 |
| **チャプターのつなぎ（ドアの部屋）** | ドアが並ぶ部屋から各チャプターへ入る形。終わったチャプターのドアの見た目が変わる | 中 |
| **並べ方の表（ランダム含む）** | チャプターの順番を1つの表で決める。「固定」「この3つからランダム」「1つだけ共通」を選べる。最初に遊んだときに順番を決めてセーブに残す | 中〜大 |
| **エンディングの分かれ** | フラグ・集めた記録の数で、どのエンディングに行くかを決める表 | 中 |
| **戦いの仕組みを止める** | 敵・HP・攻撃は**消さずに切る**（設定1つで出なくする）。追いかけてくる演出は残す | 小 |

## 4. 開発の進め方（提案）

1. **「1シーン＝短編」の作り方を決める**
   - 1シーンを「見せ場（お化けの入ったタンス）」から逆算して作る：見せ場 → その前の匂わせ → 入口と出口、の順に決める。
   - 1枚の表（スプレッドシート）にシーンを並べる：シーン名・担当・見せ場・使う演出・入口と出口・置く物。今の「指示書 → 実装」の流れ（`spec-intake`）にこの表をそのまま入れられる形にする。
2. **担当の分け方**
   - 各担当が表に「チャプター名・見せ場・道と部屋のレイアウトの絵」を書く → 組み立てる人がシーンにする。
   - セリフを細かく考えるより、「これが伝わる動き」を書いてもらう（例：花瓶を持ち上げると花が咲いている）。
3. **次回までに作る1シーン**（上陸以外）
   - 今ある部品だけで作れて雰囲気が出やすいもの：**墓を掘る**（手の動作「墓を掘る」・回想「埋葬」・雪・白い色調・ピアノ）か、**トイレのハーモニカ**（長押しで洗う・波紋が灯る・ノアは「…」だけ）。
   - 合わせて **光漏れ・字幕の太字・画面の縁** を作ると、打ち合わせで出た見た目がそろう。
4. **素材の側**
   - 角のチップは、今日出した `Docs/マップチップ素材のお願い.md`（MAP-12 壁の上面の 9 枚）がそのまま使えます。北川さんに渡す。
   - 床は寒色寄りの案を画面で比べてから描いてもらう（3-A の「床の色を寒色に寄せて試す」）。
5. **今の作業への影響**
   - 敵の仕組み・ティンパニ部屋（戦い）・2人の操作の切り替え・相棒の一言は、方針（敵なし・掛け合いを減らす）と合わない所がある。**消さずに切れるようにしておき、使うかは後で決める**。
   - マップの見た目の段階 7（本番へ広げる）は、「白ベース・寒色の床・塔の外は黒か青空」が決まってから進めるのがよい。

## 5. 決めてほしいこと

| # | 決めること | 決まると進められること |
|---|---|---|
| 1 | 次回の1シーンは何にするか（墓を掘る／ハーモニカ／ほか） | そのシーンの組み立て |
| 2 | 新しい機能のうち、どれから作るか（おすすめ：光漏れ・字幕の太字・画面の縁） | 見た目の部品づくり |
| 3 | セリフをどこまで減らすか（語りだけ／少し残す） | 語りの会話の形 |
| 4 | 敵・HP・攻撃を切るか（消さずに切る） | 戦いの設定 |
| 5 | 2人の操作の切り替え（C・F キー）を残すか | 操作の整理 |
| 6 | シーンの順番をランダムにするか・最初のシーン | 並べ方の表 |
| 7 | テーマカラー・床の色 | マップの見た目の段階 7 |
| 8 | 夢オチ・エンディングの数・裏の設定・敵組織の新しい名前 | 話の仕組み（シナリオ側） |
