# テストシナリオの書き方

イベントや部屋を作ったあと、「最後まで通して遊べるか」「ロードしても困らないか」を、**手順を書いたテキストファイル**で自動で確かめる仕組みです。
一度書いておけば、あとで別の場所を直したときに、同じ手順をもう一度流すだけで壊れていないかがわかります。

- 置き場所：`Tests/Scenarios/<名前>.txt`（UTF-8。日本語を書いてよい）
- 実行（Claude に「シナリオ ○○ を流して」と頼むか、自分で）：
  ```
  powershell -NoProfile -ExecutionPolicy Bypass -File .claude/skills/unity-playtest/scripts/scenario.ps1 -Name stage1_2_rescue
  powershell -NoProfile -ExecutionPolicy Bypass -File .claude/skills/unity-playtest/scripts/scenario.ps1 -Name all
  ```
- 結果：`expect`（確かめる）の行ごとに **PASS（合格）／FAIL（不合格）**。不合格のときは画面を撮る（`%TEMP%\ct_playtest_capture\fail_…png`）。最後に合格・不合格の数。
- **セーブは自動で守られる**：始める前にセーブ（オートセーブ枠・スロット1〜3）をバックアップし、終わったら元に戻す。テスト中は無敵（`invincible off` で切れる）。
- **キーは本当に押す**：`key E` などは、テストの間だけ「エディタが手前になくてもゲームにキーが届く」設定にして押す（終わったら元に戻す）。

## 書き方
1行に1つ。`#` から行の終わりまではメモ（行の途中に書くときは前に空白を2つ）。

```text
# Stage1_2：ランタン → 追跡 → シグル合流 → ロードしても困らない
scene Stage1_2
save on
advance all                     # 着いたときの会話を最後まで
warp -107.25,14.9               # ランタンの前
expect prompt 調べる             # キーの案内が出ている
key E                           # 本当の E キーで調べる
advance battle                  # 追跡が始まるまで会話を送る
warp -128.6,13.0                # すぐゴールへ
wait 2
advance all
expect flag Flag_Sigle_Joined on
reload                          # タイトルへ → つづきから
expect near -128.6,13.0 1.5
expect no-error
```

### 動かす命令
| 命令 | すること |
|---|---|
| `scene シーン名` | 最初の1回：そのシーンで再生を始める。2回目から：そのシーンへ移る |
| `invincible on` / `off` | 無敵（`scene` より前に `off` を書くと無敵なしで始める） |
| `save on` | セーブを有効にする（ステージから直接始めるとセーブしないので、オートセーブ・ロードを確かめるときは必ず） |
| `flag フラグ名 on` / `off` | フラグを立てる・下ろす（`Assets/Data/Flags/` のファイル名。例 `Flag_OP_Done`） |
| `advance all` / `advance 3` / `advance battle` | 会話を最後まで／3文だけ／戦闘エリアが始まるまで送る |
| `wait 2` / `wait idle` / `wait battle` / `wait scene シーン名` | 2秒待つ／会話・イベントが終わるまで／戦闘が始まるまで／そのシーンに着くまで |
| `warp x,y` | ノアとシグルをその場所へ（デバッグウィンドウのワープと同じ。座標はシーンビューで調べる） |
| `run 親/子の名前` | その物を調べた・入った扱いにする（キーを使わずに） |
| `key E` / `key Enter 300` | 本当にキーを押す（ミリ秒を書くとその間押し続ける）。キーの名前：E・Q・C・F・Tab・Space・Enter・Escape・UpArrow など |
| `button 名前` | その名前のボタンを押す（タイトル・メニューなど。例 `SlotAuto`＝オートセーブの枠、`YesButton`＝はい） |
| `tighten all` | ティンパニのペグを全部締める（タイミングは合わせられないので） |
| `kill` | 無敵を切ってノア・シグルを倒す（ゲームオーバーの確認） |
| `autosave` / `reload` / `title` | 今の場所でオートセーブ／タイトルへ → つづきから（オートセーブ）／タイトルへ戻る |
| `capture 名前` | 画面を撮る |
| `eval C#` | プログラムを直接実行する（Claude 向け） |

### 確かめる命令（`expect`）
| 命令 | 合格の条件 |
|---|---|
| `expect flag フラグ名 on` / `off` | フラグがその状態 |
| `expect party Together` / `Waiting` / `Separated` | 2人の状態が 一緒／待機／別行動 |
| `expect scene シーン名` | 今のシーン |
| `expect near x,y 半径` | 操作中のキャラがその近く（半径を省くと 1 マス） |
| `expect talk 文字` | 今出ている会話の文（名前：本文）にその文字が入っている |
| `expect idle` | 会話・イベント・暗転が動いていない（ロード後にイベントが繰り返さないかなど） |
| `expect reach all` / `expect reach 名前の一部` | 今いる場所から、調べる物・出口・出現位置（名前の一部が合う物）まで歩いて行ける |
| `expect no-error` | 始めてからコンソールにエラーが出ていない |
| `expect prompt 文字` | キーの案内（[E] 〜）にその文字が出ている |
| `expect selected 名前` | UI でその名前のボタンが選ばれている（キーボードで操作できるか） |
| `expect eval C#` | その式が true（Claude 向け） |

## 新しいシナリオを書くとき
- イベント・部屋を作ったら、その流れを1本書く。**通り道が変わるイベントのあとは `reload` と `expect near` / `expect reach` を必ず入れる**（ロードで進めなくなる不具合を防ぐ）。
- 追跡（捕まると最初からやり直し）は、`advance battle` のすぐあとに `warp` でゴールへ。
- 戦闘中に会話を長く送ると倒れることがある。無敵のまま進めて、倒れる確認は `kill` で。
- 座標・名前がわからないときは Claude に聞く（デバッグウィンドウのワープの座標、Hierarchy の名前）。
