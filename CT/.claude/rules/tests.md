# テストシナリオ（`Tests/Scenarios/` を書く・直すとき）

書き方（命令の一覧・今あるシナリオ）は `Docs/テストシナリオの書き方.md`。実行は `unity-playtest` スキルの `scenario.ps1 -Name <名前>|all`（1本 1〜2 分。run_in_background で）。

## 約束
- ファイルは UTF-8、名前は英小文字と `_`（`stage1_2_rescue.txt`）。日本語はファイルの中なら書いてよい（.ps1 と違って壊れない）。
- **1本に1つの通り道**。最後は必ず `expect no-error`。イベントやシーンの通り道を確かめるシナリオは **`reload`（タイトル → つづきから）と、その後の `expect`** まで入れる（ユーザーの指示：ロードしても困らないか）。
- オートセーブ・ロードを確かめるなら、`scene` の次に `save on`（ステージから直接始めるとセーブしない）。
- 調べる物は、できるだけ `run` ではなく **`key E`** で（E キーの経路が死んでいる不具合を見逃さない。ペグの不具合はこれで見つかった）。
- **時間で変わる物は `expect within 秒 式`・`wait until 秒 式`** で書く（決まった `wait` の秒数に頼らない）。`key X ミリ秒` の数字は本当に押す時間（11-28 から。実行役が速くなった）。
- 見た目を確かめたい場面は `capture` に加えて **`expect looks <名前> [許す%]`**（基準は `Tests/Baselines/`。見た目を正しく変えたら `-UpdateBaselines` で作り直してコミット）。
- 座標の `warp` には、何の前かをメモで書く（部屋を作り直すと座標がずれる → 不合格になったら最初に疑う）。
- 新しいシナリオを足したら、`Docs/テストシナリオの書き方.md` の「今あるシナリオ」の表にも足す。
- 不具合を直したら、それを再現するシナリオを残す（`bug-fix` スキル）。
- セーブ（オートセーブ枠・スロット1〜3）はユーザーのデータ。`scenario.ps1` がバックアップと復元をする。途中で止まったら `end.ps1` で必ず戻す。

## 変更の種類ごとの確認の範囲（2026-11-20、ユーザーと合意：実装と関係の薄い確認・調査に時間を使いすぎない）
| 変えたもの | 確かめること | 流さなくてよいもの |
|---|---|---|
| **会話の文だけ**（CSV の本文・表情。ID・行の数で流れが変わらない） | 取り込み＋`-Lint`。変えた文を `expect talk` で見ているシナリオがないか **検索**（`Tests/Scenarios/*.txt` を変えた文の一部で grep）。行の数を変えた会話を `advance 数` で送っているシナリオも検索 | シナリオ（検索で当たった物だけ流す） |
| 会話を足す・消す（流れの部品が変わる） | 取り込み → そのシーンのレシピ → そのシーンのシナリオ1本 | ほかのシーンのシナリオ |
| レシピ・シーンの配置・イベント | そのシーンのシナリオ1本（＋シーンのつながりを変えたら `full_run`） | ほかのシーンのシナリオ |
| **新しいシーン** | そのシーンの通しのシナリオ＋**直接再生のシナリオ**（`scene <名前>` で始めて、着いた場所から動かないか・すぐ出口に触れないか。11-20 の Stage1_4 で、直接再生のときだけ出口に触れる不具合を見逃した）＋シーンチェック（出現位置と出口の重なり） | |
| C#（実行時） | `unity-check`、その部品を使うシーンのシナリオ（土台なら下の「全部」） | |
| 音・見た目だけ | 撮影・耳で確かめるのはユーザーに頼む | シナリオ |
| **Claude の道具・文書だけ**（スキル・スクリプト・フック・Docs） | 変えたスクリプトを1回動かす（エディタの道具ならコンパイル＋1回実行） | シナリオ・シーンチェック・手順書の更新（11-20 合意） |

## 関係のない失敗の扱い（2026-11-20、ユーザーと合意）
- 不合格の行が**今回の変更と関係ない**（変えていないシーン・部品の確認、音・タイミングの確認など）なら、**1回だけ**その1本を流し直す。
- それでも落ちたら**調べない**。報告に「関係のない不合格（前からある・不安定）」と書き、`Docs/code-map.md` の問題点に足して先へ進む。調べるかはユーザーが決める。
- 関係があるかわからないときは、落ちた行と変えたファイルを並べて1行で判断を書く（例：「会話の文だけを変えた／落ちたのは足音の確認 → 関係なし」）。

## どれを流すか（ユーザーの指示 2026-11-19「毎回全部でなくてよい。関係ありそうな所・必要な所だけ」）
- **まず `scenario.ps1 -Affected -WhatIf`**（2026-11-28〜）：変えたファイルと `unity-playtest/data/affected.tsv` から流す物と理由を出す。`NOMAP` のファイルは下の例で手で決め、表に行を足す。そのまま流すなら `-Affected`。
- ふだんは**変えた所に関係するシナリオだけ**を `-Name` で流す（例：Stage1_2 のイベント → `stage1_2_rescue`、タイトル・はじめから → `title_newgame_continue`・`op`、ティンパニ → `timpani`・`gameover_retry`、音・見た目だけ → シナリオは要らないことが多い）。`full_run` は5〜6分かかるので、シーンのつながり（遷移・出現位置）を変えたときだけ。
- どれを流したか・流さなかった理由を報告に書く。
- **本当のキー（`key E`・`key Enter`）がまれに届かない**ことがある（長く続けて流したとき。2026-11-19 に `all` で E・Enter が3回届かず、1本ずつ流し直すと合格）。キーの直後の expect だけが不合格なら、まずその1本だけを流し直す。**2本を同時に流さない**（エディタとセーブのバックアップがぶつかる。前の実行が終わったかをプロセスで確かめる）。

## いつ全部を流すか
- 段階の区切り・提出の前（`release-check` スキル）、セーブ・シーン遷移・入力・イベントの土台（`EventSequence`・`InputBlock`・`Save`）を変えたとき。
