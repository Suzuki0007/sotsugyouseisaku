# bug-fix：不具合を直す

**再現 → 原因 → 方針（見せる）→ 直す → 戻らない仕掛けを残す → 記録** の順。推測で直さない。

## 1. 再現する
- まず `Docs/code-map.md` の「4. 問題点」と `Docs/変更履歴.md` を検索（既知の問題・最近の変更が原因のことが多い）。
- コンソール：`unity-check` の `check.ps1`（エラーの1行要約）。
- 通り道の不具合（進めない・ロードで変な所から始まる・イベントが繰り返す）：
  - 近いテストシナリオを流す：`unity-playtest` の `scenario.ps1 -Name <名前>`（`Tests/Scenarios/`）。
  - なければ `event.ps1`（`-State`・`-Advance`・`-Warp`・`-Run`・`-Reload`・`-CheckInteract`・`-Prompt`・`-Reach`）で手順をたどる。たどれた手順はそのままシナリオにできる。
- 「E で調べられない」：eval で `Interact` を呼んで動くのは**再現になっていない**。`event.ps1 -CheckInteract`（土台の Update が生きているか）で見る（`rules/coding-style.md`）。
- 再現できなかったら、何を試して再現しなかったかを書いてユーザーに条件を聞く（どのシーン・どのセーブ・どのキャラを操作していたか）。
- **ユーザーのセーブを使って再現したいとき**は、`start.ps1` のバックアップがあることを確かめてから。セーブのファイルを書き換えない。

## 2. 原因と方針
- 原因の行（ファイル:行）と、なぜそうなるかを1〜2文で。
- 直し方の候補が複数あるとき・ほかの人のコード（`rules/team-code.md`）・土台（`EventSequence`・`Save`・`PlayerMovement` など）に触るときは、**直す前に方針を見せて合意する**（CLAUDE.md「大きな設計は先に合意する」）。
- 原因の近くに別の問題を見つけたら、直さずに報告して code-map に書く（頼まれたら直す）。

## 3. 直す
- 直すのは原因の所だけ。ついでの整理はしない。
- `unity-check` → 再現の手順をもう一度 → 直っていることを確かめる。周りのシナリオ（同じシーン・同じ仕組み）も流す。

## 4. 戻らないようにする（どれか1つは必ず）
- **テストシナリオ**：再現の手順を `Tests/Scenarios/<名前>.txt` に（`rules/tests.md`）。`expect` で不具合の状態でないことを確かめる。
- **シーンチェック**：設定ミスが原因なら `SceneChecker.CheckScene`／`CheckProject` に確認を足す（ペグの Update の不具合はこれで見つけた）。
- **ルール**：書き方の落とし穴なら `rules/coding-style.md` か機能のルールに1行。
- どれも無理なら、理由を報告に書く。

## 5. 記録
- `Docs/code-map.md`：「4. 問題点」から消す（直した）・足す（見つけた🆕）。CLAUDE.md の「問題点の要約」に載っていたら消す。
- `finish-task` で締める。コミットメッセージの1行目は「〜の不具合を修正」。ほかの人のコードなら「〇〇さんへ」の段落。
