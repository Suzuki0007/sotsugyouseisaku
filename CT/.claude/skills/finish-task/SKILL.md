# finish-task：作業の締め

ユーザーとの約束（CLAUDE.md「作業のルール」）を、毎回同じ順番で守るためのチェックリスト。
**コミット・push はしない**（ユーザーが Fork で行う）。変更する Git の操作（commit・push・ブランチの切り替え・stash・reset など）は頼まれたときだけ。

## 0. 変更したファイルを確かめる（読むだけの Git）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .claude/skills/finish-task/scripts/changes.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .claude/skills/finish-task/scripts/changes.ps1 -Diff -Path Assets/Script/Gimmick
```

- Fork に同梱の Git（`%LOCALAPPDATA%\Fork\gitInstance\<版>\cmd\git.exe`）を使う。status・log・diff だけ。
- **ユーザーが触るブランチは `ueeyama_home` と `Uh_School` だけ。**今のブランチがそれ以外なら `[WARN]` が出る → ユーザーに伝える。頼まれて Git を操作するときも、この2つ以外には切り替え・コミット・マージ・push をしない。
- 一覧に**意図しないファイル**（シーン・プレハブ・`ProjectSettings`・フォント・`Assets/__ClaudeTest`）があれば、理由を確かめて報告に書く（ユーザーのテストプレイによる変更のこともある。勝手に戻さない）。
- `== changed files by other authors` に出たファイルは、ほかの人（`\author`）が書いたもの → コミットメッセージに「〇〇さんへ」の段落が要る。誰が最後に変えたかは `changes.ps1 -Log -Path <ファイル>`。
- コミットメッセージは、この一覧に合わせて書く（ユーザーの変更が混ざっているなら、自分の分だけを書き、そのことを伝える）。
- **毎回「前回のコミットからの差分すべて」で1つのメッセージにする**（ユーザーの指示）。`== last commits` の一番上が前回のコミット。未コミットの一覧にある作業は、前の依頼の分も含めて全部入れる（今回の依頼の分だけで書かない）。報告には「前回のコミット（ハッシュと1行目）からの差分」と書き添える。

## 1. 確認
- [ ] `unity-check` を実行した（エラー・自分の書いたコードの警告なし）。シーンに置く物を変えたなら `-SceneCheck` も。
- [ ] 実行時の C# を変えたなら、`perf-review` の `scripts/scan.ps1`（変更したファイル）をかけ、「1. per-frame code（hot）」の指摘を読んだ（自分の書いた毎フレームの処理に Find・GetComponent・new・文字列の組み立てがないか）。
- [ ] 動きを変えたなら `unity-playtest` で再生して確かめた（`end.ps1` まで実行した）。
- [ ] イベント・部屋・セーブ・プレイヤーの操作を変えたなら、**関係するテストシナリオ**（`Tests/Scenarios/`、`unity-playtest` の `scenario.ps1 -Name <名前>`）を流して全部合格した。**流す範囲は `rules/tests.md` の「変更の種類ごとの確認の範囲」**（会話の文だけならシナリオは検索で当たった物だけ）。新しいイベント・部屋には1本足した（新しいシーンは直接再生の1本も。`Docs/テストシナリオの書き方.md`）。
- [ ] 今回の変更と**関係のない不合格**は、1回だけ流し直し、それでも落ちたら調べずに報告して code-map に書いた（`rules/tests.md`）。
- [ ] イベント・セーブ・シーンの通り道を変えたなら、**ロードしても困らないか**を確かめた。**そのシーンのシナリオの `reload`（タイトル → つづきから）＋その後の `expect` が合格なら、それで済み**（手で試し直さない）。シナリオがない通り道だけ手で（`rules/save-ui.md`）。通り道が変わるイベントの最後に部品「オートセーブ」があるか。
- [ ] 部屋を作った・配置を変えたなら、`room-build/scripts/mapshot.ps1 -Scene <名前>` の PNG を報告に添付した（SendUserFile）。
- [ ] 謎・仕掛け・フラグの条件を変えたなら、`FlowMap.Build()` を流した（`Docs/仕掛けの流れ/` もコミットに含める）。注意が出たら直すか、受け口なら `_例外.tsv`。
- [ ] 会話を変えたなら `dialogue-csv/scripts/text.ps1 -Check`。キャラ・会話を大きく変えたら MUSE 向けの資料3の全文を `-Export` で作り直す。
- [ ] **素材（音・絵・アニメ・エフェクト）を入れた**なら、`asset-audit` の `audit.ps1 -Apply -NewSlots` で素材チェックリストを更新した（新しい空き欄は行を足すか `data/ignore.tsv` へ）。素材の欄を持つ部品を足しただけ・仮素材を置いただけのときは流さず、**段階の区切りでまとめて**流す（Excel を開くので1〜2分かかる。11-20 合意）。
- [ ] **確認できなかった項目**（キー入力・UI のフォーカス・見た目・音など）を書き出した。
- [ ] テスト用のアセット（`Assets/__ClaudeTest/`）が残っていない。シーンを勝手に保存していない（保存したなら理由を伝える）。

## 2. 文書の更新
**Claude の道具（スキル・スクリプト・フック・レシピの小道具）だけを変えたとき**は、その SKILL.md（とルール）と `Docs/変更履歴.md` だけでよい。プランナー向けの手順書・早見表・テストシナリオは要らない（11-20 合意）。

- [ ] **`Docs/code-map.md`**：「3. スクリプト一覧」に足したファイル・役割の変更。「4. 問題点」から直したものを消し、見つけたもの（直していない既存の問題）を足す（🆕）。**「最終更新」は書かない**（記録は変更履歴だけ）。
- [ ] **`.claude/rules/<機能>.md`**：触った機能の仕組みの説明（新しいクラス・セーブのキー・約束）。新しいフォルダを作ったら、どのルールの `paths:` に入るか確かめる（入らなければ足すか、新しいルールを作る）。セーブのキーを足したら `save-ui.md` の一覧にも。
- [ ] **`Docs/変更履歴.md`**：一番上の日付の節に、今回の作業を1項目（太字の見出し＋何ができるようになったか）。
- [ ] **`CLAUDE.md`**：変わったときだけ（「進み具合」の段階・問題点の要約〔高い物 3 つまで〕・道具の表・約束）。**「最終更新」は書かない。細かい仕組みは CLAUDE.md ではなく rules に書く。**
- [ ] **プランナーが使う機能**を足した・メニュー名・Inspector の項目名を変えたときだけ：その機能の手順書（`Docs/*.md`）と `Docs/プランナー向け作業手順書.md` の本文（メニュー・部品の早見表は手で書かない。自動の早見表を作り直す）。
- [ ] コンポーネント・イベントの部品・メニュー・Label／Tooltip・標準の合図を足した／変えたら、**早見表（自動）を作り直す**：`Invoke-UnityEval -Code 'return QuickReferenceBuilder.Build();'`（＝ Tools > 手順書 > 早見表を作り直す）→ `Docs/早見表（自動）.md` もコミットに含める。新しいクラスには `/// <summary>` の1行目（見出し）と「・」の行（説明）を書く（早見表にそのまま出る）。
- [ ] 仕組みの変更が大きいとき：`Docs/引き継ぎ_アイテム画面以降の変更.md`（設計の「理由」「なぜこの形か」）。
- [ ] 共有用（Claude Docs）の手順書・引き継ぎ資料は**頼まれたときだけ**反映する。大きく変えたなら「共有用にも反映しますか」と一言添える。

## 3. 報告
次の順番で、日本語で短く：
1. やったこと（プランナーから見て何ができるようになったか）
2. 確かめたこと／**確かめられなかったこと**
3. 見つけた既存の問題（直していない。code-map に追記済み）
4. コミットメッセージ

## コミットメッセージの書き方
- 日本語。1行目は 50 字くらいまでの要約、空行、本文は箇条書き（何を・なぜ）。
- 複数の作業をまとめて頼まれたら、最後にまとめて1つ。
- コードブロックで渡す（ユーザーがそのままコピーできるように）。
- **ほかの人が書いたコードを変えたときは、本文の最後に「〇〇さんへ」の段落を足す**：変えたファイルと場所、何を・なぜ変えたか、その人の作業で気をつけること（動きが変わる点・マージで重なりそうな所）。書いた人はファイル先頭の `\author` か、`git log --format="%an" -- <ファイル>` で確かめる（ユーザー＝uh / uh41 以外が対象）。

```text
謎解き：押せる箱を2人で押せるようにする

- PushBlock に「2人で押す」を追加（相棒が隣で待機しているときだけ動く）
- 手順書 12 章・早見表に追記
- code-map・rules/gimmick-party.md を更新
```
